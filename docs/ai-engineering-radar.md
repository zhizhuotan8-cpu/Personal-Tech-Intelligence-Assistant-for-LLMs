# 大模型应用工程情报助手（第一版）

默认配置已切换为行业 RSS + AI 兴趣分类 + 中文技术简报。综合热榜停止采集。

## 关注范围

Agent 40%、RAG 30%、模型/API 20%、部署 10% 是提示词中的选稿倾向，不是程序统计配额。LangChain、LangGraph、Deep Agents 优先，LlamaIndex 与 Hugging Face 补充 RAG 和工程实践。简报使用结构化 events 输出，程序限制最多 5 个事件，并按原文链接和标准化标题去重；同义事件的语义合并仍依赖模型。筛选后的 RSS 原始列表仍会保留，不受五条限制。

配置入口：

- `config/config.yaml`：17 个 RSS/Atom 来源、AI 与推送设置。
- `config/ai_interests.txt`：四类主题与排除规则。
- `config/ai_engineering_prompt.txt`：工程影响、验证方向、出处与证据限制。
- `config/frequency_words.txt`：无模型时手动切换 `filter.method: keyword` 的备用规则，不等价于 AI 分类。
- `config/timeline.yaml`：`ai_engineering_daily` 日报时段。

## 运行

在仓库目录使用 PowerShell：

```powershell
$env:AI_API_KEY = '你的密钥'
$env:AI_MODEL = '提供商/你实际可用的模型名'
.\.venv\Scripts\python.exe -m trendradar
```

`AI_MODEL` 是执行筛选和简报的模型，与订阅对象无关。建议显式设置可用模型，配置文件中的默认名称不保证账号可用。也可按已有配置设置 `AI_API_BASE`。不要把真实密钥提交到仓库。

调度按北京时间全天采集，19:00–23:00 内首次执行时分析并推送一次。调度配置本身不会启动常驻进程；需现有 Docker cron、GitHub Actions 或 Windows 任务计划定时调用，至少覆盖晚间窗口。单次本地运行在窗口外只采集，不生成 AI 简报；手动预览可暂时关闭 `schedule.enabled`，并关闭 `notification.enabled` 后执行。实际推送还需配置渠道凭据。跨运行去重依赖保留存储数据。

## 2026-11-10 网页正文摘录与快照

- `ai_analysis.fetch_evidence` 开启分析前正文获取：按分析输入顺序最多请求五个不同原文 URL，不改变前置筛选结果。
- 当前仅支持 HTTPS 的 github.com、openai.com、huggingface.co、qwenlm.github.io；跳转逐次检查站点。仅接受 HTML，提取 article/main 内容并排除脚本、导航等。动态网页或结构不兼容时降级，不能保证所有页面均能提取。
- 连接/读取超时为 5/10 秒；单页下载上限 2 MB，读取过程中检查 25 秒预算；最多四次跳转请求；每页输入最多 6000 字符。整轮五页可能需要较长时间。
- `output/evidence/<URL哈希>.json` 保存原文 URL、最终 URL、UTC 抓取时间、摘录、截断标记、响应内容 SHA256 或失败原因；成功快照复用 24 小时。保留的是摘录，不是完整 HTML 归档；快照清理尚未自动化。
- 报告证据标签由程序选择：网页摘录、RSS 摘要或仅标题。所有网页内容均视为不可信数据，不执行其中指令；正文来源并不等同于独立事实验证。
- 全量测试 46 项、52 个子场景通过；官方 LangGraph Releases 页面真实抓取成功并保存 6000 字符摘录。此次没有调用模型或发送通知，尚未验证不同站点的正文提取质量。
