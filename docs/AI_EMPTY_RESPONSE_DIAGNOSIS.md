## 已确认的问题

`AIClient.chat()` 原来只读取 `choices[0].message.content` 并返回 `content or ""`。当接口请求成功、正文却为空时，LiteLLM 的异常重试没有在此调用路径处理它，筛选和分析只能随后报失败，且没有 finish_reason/token 用量可供定位。

回归命令：`python -m pytest -q tests/test_ai_client_response.py`。修复前两个关键测试失败：暂时空正文没有重试，持续空正文没有明确异常。修复后通过。

## 真实请求观察

- 最小 JSON 请求正常：finish_reason=stop，正文 11 字符。
- 使用上次保存的 400 条公开采集数据，两次回放筛选与生成都成功。
- 同一简报请求连续三次成功，finish_reason 均为 stop，输出 token 分别为 2097、2887、2874。
- 某次筛选使用 4832/5000 输出 token，其中 3615 为推理 token，说明额度接近上限，但未捕获原失败请求的结束原因，不能据此断定历史故障是额度耗尽。

已排除当前持续性的密钥/接口不可用；未复现历史上游空返回，仍可能是上游偶发返回或输出额度问题。此次没有修改模型名、API 地址、token 配额或关闭模型推理。

## 修复边界

- 空正文最多按 NUM_RETRIES 再试两次，零重试配置得到尊重。
- 空白字符串、没有 choices 同样明确失败；正文块只提取 text，不把推理当结果。
- 过滤拒绝与工具调用不盲目重试。
- 持续失败报告结束原因和 completion token 数；不输出响应正文、推理正文、凭据或服务地址。
- 有效正文不增加调用；网络异常仍交给既有 LiteLLM 处理。应用空正文重试可能带来额外模型用量。
