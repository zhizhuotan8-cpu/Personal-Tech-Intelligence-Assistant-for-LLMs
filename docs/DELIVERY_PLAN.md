# 本地可用版交付规划

更新：2026-11-10。优先目标：用户在自己的 Windows 电脑上，用一个入口启动并看到真实行业简报。本文取代此前“先完善来源与正文，再做日常交付”的执行顺序。

## 一、调整原因与现状

当前项目已有 RSS 采集、AI 筛选、最多五条的结构化简报、输入链接校验、摘要和部分网页摘录、HTML 输出。最近记录的全量测试为 46 项、52 个子场景通过。已有真实采集和模型样本验证，但不能据此认定用户日常运行已验收。

交付缺口在入口和完整用户路径：普通启动受日报时段影响；Windows 用户环境变量可能未被现有进程继承；预览依赖临时 Python 命令；前端仍有通用舆情用语；缺少用户能直接辨认的成功、无更新与失败状态。现有说明多次追加历史记录，也增加了启动成本。

原规划的方向有用，但顺序偏向能力建设，用户迟迟看不到完整产品。立即停止扩展来源、通用抓取器和知识库，把已有能力收敛成能启动、能看、失败能处理的本地版本。沿用现有 Python + HTML，不重写技术栈。

## 二、交付顺序与验收门槛

### 第一步：先交付手动可用版（下一个开发批次）

用户路径：双击预览入口 → 校验本地配置 → 显示采集与分析进度 → 打开本地 HTML 简报。

必须完成：

1. 提供 Windows 一键预览入口和正式的预览命令。读取当前进程配置，缺失时补读 Windows 用户环境变量；不打印密钥、不把凭据写入文件。
2. 预览强制关闭通知，绕过晚间调度，使用隔离的预览输出，不占用正式日报的一次执行记录。默认真实采集、真实调用用户配置的模型。
3. 默认利用 RSS 摘要；网页正文获取在预览中作为可选增强，避免五页串行请求拖慢第一次体验。现有配置支持的完整模式保留。
4. 报告首页优先展示工程简报与原文链接，隐藏无内容的舆情栏目；展示生成时间、来源成功/失败数和证据范围。沿用现有 HTML，不新建复杂 Web 服务。
5. 区分“成功生成”“本次无值得推荐的更新”“部分来源失败”“模型或运行失败”。失败不伪装成无更新，不让旧报告看起来像本次成功；命令失败需返回非零退出码。
6. 提供独立的样本演示选项，允许在网络或模型不可用时查看界面。页面显著标注“样本演示”及样本时间，不能自动把样本当真实日报。
7. 提供一页快速开始文档，只写启动入口、结果位置和常见失败处理。

验收：在用户当前电脑上从正式入口跑通一次真实“采集 → 筛选 → 分析 → HTML”，并检查报告内容和链接；关闭通知；验证无更新和失败状态；验证样本演示与真实运行明确区分。记录实际耗时和瓶颈，不预先承诺固定完成秒数。单独样本回放通过不算完整真实链路验收。

交付物：可双击入口、正式 CLI 预览参数、可查看的报告、快速开始文档、相关测试与简短中文 Git 提交。先让用户拿到这个版本，再扩展下一步。

### 第二步：从手动可用变成每天可用

第一步验收后执行：

- 先沿用本地 HTML 阅读，提供 Windows 任务计划的安装、状态查看和卸载方式；核实解释器绝对路径、工作目录、用户环境变量和北京时间窗口。
- 验证重复启动不会重复分析或推送，采集失败有日志，用户能找到最新成功报告。
- 如用户选择通知渠道，再接入该渠道并完成授权范围内的发送验证；没有渠道不阻塞本地日报交付。
- 日志与缓存有清理规则，减少持续运行后的维护负担。

验收：真实计划任务至少成功执行一次，用户无需打开开发工具即可找到当天结果；跨运行去重通过。连续数日观察另记为试运行，不以一次触发冒充长期稳定。

### 第三步：根据使用结果改善情报质量

- 连续查看实际日报，记录有用内容占比、重复事件、漏报和阅读耗时。先人工记录，不急于开发反馈系统。
- 优先修复实际出现的问题：只有版本号导致漏选、网页摘录导航噪声、旧分类缓存、营销条目混入和同事件转载。
- 逐个补高价值厂商公告、API 弃用与 Changelog 来源；新增来源必须验证真实内容和工程价值。
- 根据实际需要补语义去重、独立重要弃用提醒与正文适配器。

验收：以用户实际阅读记录决定优先级，不把采集数量或测试数量当成情报质量。

## 三、本地首版不作为前置条件的能力

暂缓：全面模型厂商覆盖、通用网页抓取、多 Agent、向量数据库、完整事件聚类、收藏管理界面、周报、长期知识库、登录系统、云部署和移动端。现有证据能力保留，但不继续扩展后才交付界面。

## 四、执行规则

- 下一个批次只执行第一步，包含实现、真实链路验证、报告检查和交付，避免再次只完成底层模块就结束。
- 若真实运行被网络或模型阻塞，明确显示原因，同时交付已标注的样本演示；记录未通过的验收项，继续排障，不宣布真实链路完成。
- 保留已有 index.html 和 .python-version 的用户改动；仅暂存本批文件。测试通过后使用简短中文提交并推送 GitHub；网络失败如实报告。
- 本规划不代表新增功能已经实现。第一步完成后更新状态，再进入第二步。
